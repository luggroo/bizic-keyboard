# 输入响应、启动与内存

## 正式安装包

0.3.1（版本码 6，SHA-256 `059e2930521f1855272d8432c0002447a90543dada86e695fcfa08e31912077b`）在 Android 9 / API 28 的 x86_64 软件模拟器上完成了 64 次输入。32 次打开记音候选后点“架”，32 次在邮箱栏点字母 a，每次均写入并绘制了预期正文。屏幕为 480 × 800 像素、160 dpi，系统字号 100%。设备独占测试，云宿主也在运行另一台模拟器。

| 操作与终点 | P50 | P95 | 最大 | ≤30 ms |
| --- | ---: | ---: | ---: | ---: |
| 单击 a，编辑器正文更新 | 26.2 ms | 55.3 ms | 63.6 ms | 20/32 |
| 单击 a，宿主绘制完成 | 71.1 ms | 104.0 ms | 237.0 ms | 0/32 |
| 点“架”，编辑器正文更新 | 68.1 ms | 129.2 ms | 170.6 ms | 2/32 |
| 点“架”，宿主绘制完成 | 122.7 ms | 203.8 ms | 219.1 ms | 0/32 |

两种输入在这台软件模拟器上均未达到 P95 ≤30 毫秒。每组 32 个样本，最近秩 P99 等于该组最大值。从重置绘帧统计到两类操作结束，Android 为输入法记录 301 帧，均标为卡顿，帧耗时 P50 为 105 毫秒，P95 为 250 毫秒，P99 为 400 毫秒。结束时输入法进程 PSS 为 32,651 KiB（31.9 MiB），交换 PSS 为 0。物理手机的显示和长期内存情况仍待实测。[每次输入、帧和内存原始数据](results/api28-031-final-keys.log)

## 0.3.1 连续点按和手势

0.3.1（版本码 6，构建 `dbcf9f1c…`）在 Android 9、x86、SwiftShader 软件模拟器上连续点击同一个字母键 180 次，180 次都在外部邮箱输入框中收到并绘制了正确正文。抬指到正文更新的 P50 为 45.3 毫秒，P95 为 197.4 毫秒；到宿主绘制的 P50 为 99.5 毫秒，P95 为 295.6 毫秒。手指滑出、系统取消触摸均未误输入。连续退格、长按元音选调、长按候选查看全文、单击候选提交和搜索动作均通过。[180 次独立记录](results/api28-031-letters.log) · [手势及功能键记录](results/api28-031-gestures.log)

0.3.0 正式包在 96 次快速同键点击中曾漏收 1 次。追踪版用同一节奏重现了 3 次。三次都是同一按钮收到按下和抬起，但抬起时按压状态已经清除，没有触发点击或向宿主提交文字。0.3.1 改为追踪每次触摸的起止和取消事件。[正式包失败样本](results/api28-x86-c9f35807-repeats.log) · [事件轨迹](results/api28-x86-tap-trace.txt)

## 键盘启动

在同一台 Android 9 模拟器上，正式包 0.3.1 每次均从系统键盘切入。三次进程冷启动的结果如下。

| 操作与终点 | 第一次 | 第二次 | 第三次 |
| --- | ---: | ---: | ---: |
| 键盘上的“汉字记音”可见 | 3.38 秒 | 3.35 秒 | 4.87 秒 |
| 键入 `ga` 后，“吃、咬／架”可选 | 4.74 秒 | 4.71 秒 | 6.48 秒 |

词库加载完成后，收起键盘再从同一输入框打开，8 次暖启动耗时为 0.64 至 1.28 秒，P50 为 0.87 秒。这些时间含系统切换、窗口更新和无障碍节点检索。[正式安装包启动原始记录](results/api28-031-final-startup.log)

## 测量口径

独立的 Android 测试应用显示两个输入框。第一个使用普通文本控件，连续键入 `ga` 后点“吃、咬／架”。第二个使用邮箱控件，反复点 `a`。每次都核对外部编辑器收到的完整字符串。每种操作先预热两次。触摸事件注入、时钟、输入法和编辑器都在同一台 Android 设备上，按键计时包含系统调度和跨进程通信。

- **文字变化**从测试程序将抬指事件交给系统前一刻计到外部 `EditText.onTextChanged` 收到预期正文。
- **宿主绘制**从同一次抬指计到带新文字的 `EditText.onDraw` 返回。显示器实际亮起新像素还需等待合成与扫描输出。
- **进程冷启动**先选系统键盘、停止土家语输入法并核实无 PID，再从请求系统切换输入法时计时。分别记录无障碍窗口可见“汉字记音”和键入 `ga` 后可见“吃、咬／架”的时刻。系统文件缓存保持原状。后者包含自动点击模式和两个字母的时间。
- 采用紧凑布局的版本用常驻「打字」按钮判断键盘可见，检查词库前通过「更多」切换为汉字记音。
- **暖启动**在词库已加载的同一进程里收起键盘。从宿主调用 `showSoftInput` 计到可访问树可读“汉字记音”。启动端点含无障碍查询和线程调度耗时。

分位数使用最近秩，P95 为排序后第 ⌈0.95 × 样本数⌉ 个值。冷启动只有 3 次，逐次值比尾部分位更有参考意义。模拟器结果只代表该系统映像、软件渲染和云宿主负载。评估手机的 30 毫秒目标时，可用相同程序在实机上重测。要取得实际显示时刻，还需要屏幕采样或硬件光学测量。

## 超长草稿

Linux x86_64 主机使用 `-O2` 构建同一分词核心，每个长度启动一个新进程。载入完整词库、词级及音节联想表后查询一次。表中给出识别得到词的 `gaf` 重复串，以及没有首词的 `q` 重复串。单位为毫秒，每格一次测量。

| 草稿字符数 | 可识别的拼写 | 无首词的拼写 |
| ---: | ---: | ---: |
| 32 | 0.082 | 0.023 |
| 256 | 0.313 | 0.033 |
| 1,024 | 1.665 | 0.065 |
| 4,096 | 3.921 | 0.084 |
| 16,384 | 16.574 | 0.326 |
| 65,536 | 72.668 | 1.212 |

65,536 个字符的可分词草稿使进程峰值 RSS 从载入词库后的 13.6 MiB 增至 17.3 MiB，完整返回 8 个候选。拼写键每次更新都会在输入法主线程查询当前整串草稿。极长草稿持续逐键输入会积累计算成本，这张表只测最后一次查询。手写区域每字最多保留 64 笔，每笔最多保留 2,048 个采样点。[原始读数](results/lookup-stress.csv)

## 复现

在解锁的独占测试设备上安装待测输入法，启用一个备用系统键盘。脚本会恢复此前的默认输入法和实体键盘显示设置。以 Android 9 的 LatinIME 为例：

```bash
./tools/build-apk.sh --performance-test /tmp/tujia-perf.apk
./qa/measure-android.sh /tmp/tujia-perf.apk build/perf com.android.inputmethod.latin/.LatinIME
```

结果目录保存受测 APK 摘要、设备信息、每次测量和原始 `dumpsys` 输出。通过 `ANDROID_SERIAL` 选择设备，`COLD_ROUNDS`、`WARM_ROUNDS`、`KEY_ROUNDS` 分别控制三种样本数。设置 `PERF_PROFILE=letters KEY_ROUNDS=180` 可只测连续点按，`PERF_PROFILE=keys` 可只测两类输入，`PERF_PROFILE=startup` 可只测启动，`PERF_PROFILE=gestures` 可运行取消、滑出、长按、候选和搜索动作。

```bash
c++ -std=c++17 -O2 -Ishared/src qa/lookup-stress.cpp shared/src/lexicon.cpp -o /tmp/tujia-stress
for n in 32 256 1024 4096 16384 65536; do
  for word in gaf qqq; do
    /tmp/tujia-stress shared/bundle/Assets/words.tsv shared/bundle/Assets/ngrams.tsv shared/bundle/Assets/syllable_bigrams.tsv "$n" "$word"
  done
done
```
