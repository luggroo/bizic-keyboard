# 输入响应、启动与内存

## Android 9 模拟器结果

0.3.0 的 0d5ef60f 构建在 Android 9 / API 28 的 x86_64 软件模拟器上运行。窗口为 480 × 800 像素、160 dpi，字体比例 1.0。设备内独占测试，云宿主也运行另一台模拟器。测试前两种输入各预热 2 次，之后每组重复 32 次。

| 操作与终点 | P50 | P95 | 最大 | ≤30 ms |
| --- | ---: | ---: | ---: | ---: |
| 单击 a，编辑器正文更新 | 31.9 ms | 110.7 ms | 117.8 ms | 14/32 |
| 单击 a，编辑器绘制结束 | 81.4 ms | 536.3 ms | 600.4 ms | 0/32 |
| 点“架”，编辑器正文更新 | 67.0 ms | 230.8 ms | 428.1 ms | 1/32 |
| 点“架”，编辑器绘制结束 | 104.8 ms | 349.7 ms | 564.9 ms | 0/32 |

此设备上的两条输入路线均未达到 P95 ≤30 ms。每组有 32 个样本，此处 P99 等于最大值。文字、绘制两个时刻可以从同一条样本的编号对应查看。[逐次结果](results/api28-0d5ef60f.log)

冷启动 3 次，出现可访问的模式按钮分别用 4.79、4.04、4.06 秒，第一条已知候选分别在 6.60、4.97、5.36 秒出现。暖启动共 8 次，模式按钮可见的 P50 为 1.66 秒，最大值为 6.15 秒。这些结果包括系统开窗和获取可访问节点的时间。

从键盘展开后重置 Android 的绘制计数，到两类输入结束，`gfxinfo` 为输入法记录 314 帧，其中 314 帧被系统计为卡顿。帧耗时 P50 为 121 ms，P95 为 450 ms，P99 为 650 ms。测试结束时输入法的进程 PSS 为 47,373 KiB（46.3 MiB），交换 PSS 为 0。这是启动词库、输入 68 次并切换编辑框之后的单个观测点。物理手机上的端到端输入、功耗和长时间内存走势仍待实测。

在 32 位 Android 9 软件模拟器上对 184ee1ff 构建做了另一轮测试。32 次选“架”均收到正确正文且绘制完成。直输第 24 个计入统计的样本在 8 秒观察窗口内没有同时满足“正文正确、重新绘制”两个条件，测试提前停止。这次没有取得完整的延迟或内存汇总。[该次设备日志](results/api28-x86-184ee1ff.log)

## 测量口径

独立的 Android 测试应用显示两个输入框。第一个使用普通文本控件，连续键入 `ga` 后点“吃、咬／架”。第二个使用邮箱控件，反复点 `a`。每次都核对外部编辑器收到的完整字符串。每种操作先预热两次。测试注入触摸事件，时钟、输入法和编辑器都在同一台 Android 设备上。

- **文字变化**从测试程序将抬指事件交给系统前一刻计到外部 `EditText.onTextChanged` 收到预期正文。
- **宿主绘制**从同一次抬指计到带新文字的 `EditText.onDraw` 返回。显示器实际亮起新像素还需等待合成与扫描输出。
- **进程冷启动**先选系统键盘、停止土家语输入法并核实无 PID，再从请求系统切换输入法时计时。分别记录无障碍窗口可见“汉字记音”和键入 `ga` 后可见“吃、咬／架”的时刻。系统文件缓存保持原状。后者包含自动点击模式和两个字母的时间。
- **暖启动**在词库已加载的同一进程里收起键盘。从宿主调用 `showSoftInput` 计到可访问树可读“汉字记音”。启动端点含无障碍查询和线程调度耗时。

分位数使用最近秩，P95 为排序后第 ⌈0.95 × 样本数⌉ 个值。冷启动只有 3 次，逐次值比尾部分位更有参考意义。模拟器结果只代表该系统映像、软件渲染和云宿主负载。评估手机的 30 毫秒目标时，可用相同程序在实机上重测。要取得实际显示时刻，还需要屏幕采样或硬件光学测量。

## 超长草稿

Linux x86_64 主机使用 `-O2` 构建同一分词核心，每个长度启动一个新进程。载入完整词库与联想表后查询一次。表中给出识别得到词的 `gaf` 重复串，以及没有首词的 `q` 重复串。单位为毫秒，每格一次测量。

| 草稿字符数 | 可识别的拼写 | 无首词的拼写 |
| ---: | ---: | ---: |
| 32 | 0.085 | 0.038 |
| 256 | 0.433 | 0.039 |
| 1,024 | 0.990 | 0.047 |
| 4,096 | 7.149 | 0.110 |
| 16,384 | 16.321 | 0.430 |
| 65,536 | 69.106 | 1.240 |

65,536 个字符的可分词草稿使进程峰值 RSS 从载入词库后的 13.1 MiB 增至 16.7 MiB，完整返回 8 个候选。拼写键每次更新都会在输入法主线程查询当前整串草稿。极长草稿持续逐键输入会积累计算成本，这张表只测最后一次查询。手写区域每字最多保留 64 笔，每笔最多保留 2,048 个采样点。[原始读数](results/lookup-stress.csv)

## 复现

在解锁的独占测试设备上安装待测输入法，启用一个备用系统键盘。脚本会恢复此前的默认输入法和实体键盘显示设置。以 Android 9 的 LatinIME 为例：

```bash
./tools/build-apk.sh --performance-test /tmp/tujia-perf.apk
./qa/measure-android.sh /tmp/tujia-perf.apk build/perf com.android.inputmethod.latin/.LatinIME
```

结果目录保存受测 APK 摘要、设备信息、每次测量和原始 `dumpsys` 输出。通过 `ANDROID_SERIAL` 选择设备，`COLD_ROUNDS`、`WARM_ROUNDS`、`KEY_ROUNDS` 分别控制三种样本数。

```bash
c++ -std=c++17 -O2 -Ishared/src qa/lookup-stress.cpp shared/src/lexicon.cpp -o /tmp/tujia-stress
for n in 32 256 1024 4096 16384 65536; do
  for word in gaf qqq; do
    /tmp/tujia-stress shared/bundle/Assets/words.tsv shared/bundle/Assets/ngrams.tsv "$n" "$word"
  done
done
```
